TASK BRIEF QA-SMOKE-01
REQUEST: A tiny, disposable QA fixture for the AI Office itself — one pure TypeScript money/rounding helper module plus one `bun` test file, living under `.ai/office/tests/qa-smoke/`. It exists only to exercise the plan → implement → QA loop. It must not touch any production file.
AFFECTED FILES: new: .ai/office/tests/qa-smoke/money.ts
new: .ai/office/tests/qa-smoke/money.test.ts
APPROACH: Two self-contained files, no imports outside themselves. `money.ts` is a pure module with zero imports: `roundToCents(value: number): number` = `Math.round(value * 100) / 100`, and `formatMoney(amount: number, currency = "THB"): string` = round to cents, render with exactly 2 decimals (`toFixed(2)`), group integer digits in thousands with commas, prefix `฿` for `THB`, `$` for `USD`, and no symbol for any other currency; a negative amount keeps the minus sign before the symbol (e.g. `-฿1,234.50`). `money.test.ts` imports only `{ test, expect }` from `bun:test` and the two helpers from `./money.ts`, with exactly 7 test cases: (1) `roundToCents(10.455)` → `10.46`; (2) `roundToCents(19.99)` → `19.99`; (3) `roundToCents(100)` → `100`; (4) `formatMoney(1234567.89)` → `"฿1,234,567.89"`; (5) `formatMoney(42)` → `"฿42.00"`; (6) `formatMoney(-1234.5)` → `"-฿1,234.50"`; (7) `formatMoney(9.5, "USD")` → `"$9.50"`. No app, package, backend, DB or config file is read at design time; the only thing the test run touches at runtime is the existing `bunfig.toml` preload (see RISKS). Environment verified before writing this brief: `bun --version` → `1.4.4` (exit 0), so the promised command exists.

RISKS: The root `bunfig.toml` sets `preload = ["./backend/tests/setup.ts"]`, so every `bun test` run loads that backend file at runtime. It is never modified, and with nothing configured it only prints the skip notice; but if `TEST_DATABASE_URL` or a production-looking `DATABASE_URL` were set, the preload aborts the run with `REFUSING TEST AGAINST PRODUCTION DATABASE` (exit ≠ 0). Criterion 5 pins the safe configuration. Floating-point arithmetic is the second risk: `roundToCents(10.455) === 10.46` holds only because `10.455 * 100` is `1045.5000000000002`; the tests pin the real JS behavior of `Math.round`, and any "clever" alternative implementation that fails case 1 is wrong, not the test. Third, the thousands-grouping regex must not insert a comma between the minus sign and the digits (case 6 guards this). Fourth, a bun version change could alter output wording — criteria were written against bun 1.4.4, the version installed on this host.
